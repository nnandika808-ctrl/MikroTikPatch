# Metode v6 — loskiq (6.49.23), status SPK-1

**Kesimpulan:** jalur v6 bisa dikerjakan dengan kode elseif/loskiq yang ada, tapi **belum bisa dipakai apa adanya**. Tiga hal harus diporting dulu. Tidak ada blocker struktural seperti `loader.7z`.

**Status gate SPK-1:** LULUS dengan syarat porting (daftar di §4). Kalau porting gagal, v6 tetap best effort sesuai keputusan 5.

## 1. Fakta yang sudah diverifikasi

Semua diambil dari `mikrotik-6.49.23.iso` (27.781.120 B, HTTP 200) dan `all_packages-x86-6.49.23.zip` (25.856.152 B).

| Fakta | Bukti |
|---|---|
| Paket sistem bernama `system-6.49.23.npk`, bukan `routeros-*` | isi ISO: `system-6.49.23.npk`; tidak ada `routeros-*` |
| Magic npk v6 identik dengan v7 | `1ef1d0ba` = `0xbad0f11e` LE di offset 0 |
| Layout tanda tangan npk v6 sama | part `SIGNATURE` 132 B = 20 B SHA1 + 48 B KCDSA + 64 B EdDSA, sama seperti v7 |

| Logo stok identik dengan versi lain | `nova/lib/console/logo.txt`, sha256 `438e1067…a56f7`, 510 B |
| CHR v6 = image MBR + boot code mentah + 3 squashfs | `hsqs` di 6300160 / 6799872 / 23577088 |

## 2. Cacat loskiq yang harus ditutup

`loskiq/patch.py` `patch_squashfs`:

1. **keyman tidak pernah dipatch di v6.** Blok `if 'mode' in files and 'keyman' in files:` tidak pernah benar karena v6 tidak punya `mode`, lalu `keyman` masuk daftar skip di loop generik. Akibat: public key lisensi stok tetap hidup di `keyman`. Ini bug paling berbahaya karena build tetap "sukses".
2. **Tidak ada rewrite URL** sama sekali. `upgrade.mikrotik.com` di `net` dan `sys2` akan tetap menunjuk MikroTik.
3. **Tidak ada penanganan banner** — tidak masalah, karena banner stok memang yang diinginkan (keputusan 7). Cukup jangan menyalin `logo.txt` apa pun.
4. **Tidak ada penanganan loader** — juga tidak masalah untuk v6 (§3).

`fileman` (penyimpan key npk-sign) juga hanya terpatch karena kebetulan lewat loop generik; pastikan tidak ikut ter-skip saat menambah pengecualian baru.

## 3. Loader dan CHR v6

- Loader v6 = loader stok MikroTik (`nova/bin/loader`, 71.972 B untuk 6.49.23). Loader v6 **tidak punya tabel guard di `0x153e4`** (dibaca sampai 87.012 B → melewati EOF) dan tidak butuh `mode2`. Jadi loader elseif tidak dipakai; `patch_loader` boleh dilewati, dan `loader.7z` tidak relevan untuk v6.
- **`patch_block` tidak diperlukan.** CHR v6 dibangun dari nol (`sfdisk` → mount → salin `boot/` + `bin/` hasil patch → `chroot … /bin/milo /boot` → umount → konversi format), bukan dengan menambal image stok. Kalau nanti memilih jalur menambal image stok in-place, boot code di sektor 1–… tidak memuat public key (sudah diperiksa, 0 kemunculan), jadi tetap tidak perlu patch_block untuk alasan key.

## 4. Rencana porting (wajib, berurutan)

1. Salin `patch.py` ke `methods/v6/` lalu ubah `patch_squashfs`:
   - ganti gerbang `if 'mode' in files and 'keyman' in files:` menjadi `if 'keyman' in files:` dan patch `keyman` di situ;
   - hapus `keyman` dari daftar skip loop generik;
   - tambahkan tabel `url_replacements` yang sama seperti v7 (`MIKRO_UPGRADE_URL`, `MIKRO_LICENCE_URL`, `MIKRO_CLOUD_URL`, `MIKRO_CLOUD2_URL`) — tidak ada renew di v6.
2. Verifikasi bahwa `net` ikut terpatch (v6 memakai `net`, bukan hanya `sys2`).
3. Jalankan audit dengan `audit_keys.py` (5 file harus bersih) sebelum menyentuh ISO.
4. Baru rakit ISO/IMG/CHR.

Batas aman: host pengganti (`16.79.7.181`, 11 B) lebih pendek dari `upgrade.mikrotik.com` (20), `licence.mikrotik.com` (20), `cloud.mikrotik.com` (18), `cloud2.mikrotik.com` (19) — `bytes.replace` tidak akan memotong.
